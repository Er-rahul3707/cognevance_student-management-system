# Cognevance Student Management System

A responsive student directory with a vanilla JavaScript frontend and a layered Spring Boot REST API backed by MySQL. It supports student enrollment CRUD, server-side search, validation, duplicate-email protection, and directory statistics.

## Features

- Create, view, update, search, and delete student records.
- Search by name, email, course, or numeric student ID.
- Required field, email, phone, and enrollment-date validation.
- Case-insensitive unique email enforcement at service and database levels.
- Responsive dashboard with total, course, and current-month enrollment counts.
- Accessible labels, modal form, confirmation prompt, loading and empty states, and toast feedback.
- Structured REST errors without stack traces; configuration through environment variables.

## Technology

Java 17, Spring Boot 3.3.5, Spring Web, Spring Data JPA, Jakarta Validation, Maven, MySQL 8, HTML, CSS, vanilla JavaScript, and JUnit 5/Spring MockMvc. H2 is used only by the automated integration tests.

## Architecture

`backend/src/main/java/com/cognevance/students` contains the Spring application. `student` holds the entity, validated request DTO, repository, service, and REST controller. `shared` formats API errors, and `config` configures CORS. `frontend` is a static single-page dashboard. `database/schema.sql` creates the local database and restricted application user.

## Prerequisites

- JDK 17 or newer.
- Maven 3.6+.
- MySQL 8.x for the running application.
- A static file server for the frontend (for example, Python 3).

## MySQL and environment setup

From a MySQL administrator session, run `database/schema.sql`. Change the example password in that script to a strong local password before running it. Copy `.env.example` to `.env` for reference, then export its values in your shell; Spring does not load `.env` files automatically. Never commit `.env`.

PowerShell example (replace the password locally):

```powershell
$env:DB_URL = 'jdbc:mysql://localhost:3306/student_management?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC'
$env:DB_USERNAME = 'student_app'
$env:DB_PASSWORD = 'your-local-password'
$env:CORS_ALLOWED_ORIGINS = 'http://localhost:5500,http://127.0.0.1:5500'
```

The application uses Hibernate `update` to create/update the student table on startup. For production, use a managed migration process and set `spring.jpa.hibernate.ddl-auto=validate`.

## Run locally

In one terminal, configure the environment and start the API:

```powershell
mvn -f backend/pom.xml spring-boot:run
```

In another terminal, serve the frontend from the repository root:

```powershell
python -m http.server 5500 --directory frontend
```

Open <http://localhost:5500>. The frontend expects the API at `http://localhost:8080/api`. For a separately hosted API, set `window.API_BASE_URL` before `app.js` loads, or edit the `API_BASE_URL` constant in `frontend/js/app.js`; configure the API's `CORS_ALLOWED_ORIGINS` to the exact frontend origin. Do not expose DB credentials in frontend code.

## API reference

All request and response bodies are JSON. Dates use ISO `YYYY-MM-DD`. Errors have `{ "timestamp", "status", "error", "message", "fieldErrors" }`.

| Method | Endpoint | Description | Success |
| --- | --- | --- | --- |
| GET | `/api/students` | List all students, newest ID first | 200 |
| GET | `/api/students?q=asha` | Search name, email, course, or ID | 200 |
| GET | `/api/students/{id}` | Read one student | 200 |
| POST | `/api/students` | Create a student | 201 |
| PUT | `/api/students/{id}` | Replace student fields | 200 |
| DELETE | `/api/students/{id}` | Delete a student | 204 |

Student JSON:

```json
{
  "id": 1,
  "fullName": "Asha Patel",
  "email": "asha@example.com",
  "phone": "+91 98765 43210",
  "course": "Computer Science",
  "enrollmentDate": "2025-01-10",
  "createdAt": "2025-01-10T10:20:30Z"
}
```

Create request:

```bash
curl -X POST http://localhost:8080/api/students \
  -H 'Content-Type: application/json' \
  -d '{"fullName":"Asha Patel","email":"asha@example.com","phone":"+91 98765 43210","course":"Computer Science","enrollmentDate":"2025-01-10"}'
```

The `id` and `createdAt` properties are generated by the server. `fullName`, `email`, `course`, and `enrollmentDate` are required; phone is optional. Invalid input returns 400, duplicate email returns 409, missing IDs return 404, and database outages return a generic 503 response.

## Deployment

Host the Spring Boot jar on a Java 17-capable service and provision a managed MySQL 8 database reachable from it. Set `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, `SERVER_PORT`, and `CORS_ALLOWED_ORIGINS` in the backend host's secret/environment settings. Package with `mvn -f backend/pom.xml package` and run `java -jar backend/target/student-management-1.0.0.jar` (or the generated jar filename). Host `frontend/` on any static web host over HTTPS and point `API_BASE_URL` at the deployed API base URL before `app.js` loads. Apply HTTPS, database backups, network restrictions, secret rotation, and schema migrations before production use. No deployment has been performed.

## Known limitations and next steps

- The list endpoint returns all matching rows; pagination is not implemented.
- Authentication/authorization, audit logging, and migrations are outside this internship scope.
- Course statistics are calculated from the currently fetched list; the API does not expose aggregated analytics.
- Add pagination, authentication, Flyway migrations, and deployment health monitoring as future enhancements.
